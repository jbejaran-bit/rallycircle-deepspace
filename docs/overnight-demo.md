# RallyCircle in three minutes

Use the published stable product review on an approved disposable target. Ask two test participants to sign in before recording. Use a third dedicated test identity if the waitlist step is part of the recording. Prepare only the session needed for the walkthrough and label it as demo data.

| Time | Show |
| --- | --- |
| 0:00–0:25 | Start at the landing page. Open **Find Games** and show the sign-in handoff, then switch to the signed-in host's Dashboard. |
| 0:25–1:00 | Find a court and start a future singles rally. Set capacity to two, confirm the host RSVP, and share the invitation. A second account joins from the same link. |
| 1:00–1:30 | A third test account joins the waitlist. The guest withdraws and the third account is promoted. Send one short message and show it arrive from the other context. |
| 1:30–2:25 | Open the live scoreboard and Courtboard. Add a score point and move a court marker. Show the calendar file on the same session. Use a pre-scored disposable match if there is time to demonstrate both players confirming a result. |
| 2:25–3:00 | Explain that capacity and score commands are checked server-side. Open Dashboard to show what is next. Mention which browser and runtime checks were actually run. |

RallyCircle uses a static public entry and a sign-in-gated application shell. DeepSpace subscriptions carry session and attendance changes. The per-session command room serializes operations such as waitlist promotion and revisioned scoring. Courtboard uses a separately authorized collaborative room.

If sign-in or a disposable app is unavailable, present the public browser checks and screenshots and describe the match-day walkthrough as a rehearsal plan. Advanced profiles, match-history projections, polls, recurring sessions and the inbox belong to the separate advanced preview. Verify them on an approved disposable app before demonstrating them as live.
